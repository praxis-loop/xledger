# Xledger 移动端导航与排版优化设计

日期：2026-07-18
状态：设计已确认，等待书面规格复核
目标版本：`main`（当前基线 `868e586`）

## 1. 背景与目标

上一轮已经完成 iOS 基础视觉改造，但移动端仍存在三个核心问题：顶部工具栏承担语言、账户、设备和退出操作，挤占首屏；交易页延续桌面式卡片与按钮层级，空间松散；导入页上传区域过高，流程层级不清晰。

本轮只优化移动端导航与页面排版，并保持桌面端现有导航、后端协议、数据库配置和已上线的 iOS 基础样式不变。

## 2. 已确认的方案

采用 **B：独立“我的”页面**。移动端底栏固定为五项：

1. 首页
2. 交易
3. 统计
4. 账户
5. 我的

“导入”和“设置”不再占用固定 Tab。A 方案的 bottom sheet 与 C 方案的锚定 popover 均不实现。

## 3. 移动 App Shell 与“我的”页面

### 3.1 响应式边界

- 在宽度小于 1000px 时隐藏 TopBar 的可见工具栏，由底部 Tab Bar 和页面内标题承担导航。
- 在宽度达到 1000px 时保留当前桌面 TopBar、SideNav 和内容间距。
- 底部 Tab Bar 支持左右与底部 safe area，所有主要触控目标至少 44px。

### 3.2 “我的”页面结构

新增移动端独立“我的”页面，路由为 `/me`。页面从上到下包含：

- 个人资料摘要：头像、显示名称、邮箱；点击后进入现有个人资料编辑流程。
- 中文 / English 双段切换控件；切换后立即使用现有 i18n 状态更新界面。
- 第一组：导入数据、移动设备。
- 第二组：通知、帮助、设置。
- 独立危险操作组：退出登录。

该页面使用 iOS grouped list 层级，不使用外层大卡片，也不把所有内容塞进一个 Dialog。

### 3.3 业务逻辑复用

TopBar 当前拥有个人资料、密码、通知、帮助、设备和退出相关状态与业务逻辑。实现时只抽取本轮需要共享的账户操作与 Dialog 组件，使桌面 TopBar 与移动“我的”页复用同一逻辑；不得复制认证、资料保存或退出逻辑，也不进行无关重构。

## 4. 交易页移动布局

桌面交易页保持现状；以下规则只应用于小于 1000px 的布局。

### 4.1 标题与操作

- 去掉整个页面的外层大卡片，内容直接位于系统背景上。
- 页面标题使用约 32–34px 的移动端大标题。
- 标题右侧只保留两个入口：省略号菜单与“添加交易”主操作。
- 导入、现有导出操作和现有统计类低频操作进入省略号菜单；功能和权限保持不变。
- 列表 / 日历 segmented control 位于标题下一行，并占满可用宽度。

### 4.2 智能视图与筛选

- “智能视图”改为纵向 grouped list：待复核、未分类、疑似重复、大额交易。
- 每行显示名称、数量和 chevron，整行可点击。
- 常用筛选使用单行横向滚动 chip；高级筛选继续折叠。
- 导出数量等辅助信息改成轻量文字，不再单独使用胶囊或卡片。
- 空状态保持紧凑，不用大面积占位容器。

### 4.3 交易列表

交易列表自身可使用白色分组容器，但避免卡片套卡片。每行保持现有数据、编辑入口与交互，不改变交易查询和写入协议。

## 5. 导入页移动布局

### 5.1 页面结构

- 页面顶部提供明确的“返回”入口与约 32px 标题。
- 显示三步进度：选择文件、字段确认、导入结果。
- 上传区高度控制在约 180–220px，包含上传图标、简短说明和“浏览文件”主操作。
- 上传区下方使用 grouped list 展示 CSV 格式、UTF-8 编码与隐私说明。

### 5.2 状态流

- 选择文件后，上传区原位切换为文件摘要与继续操作。
- 字段映射、校验错误和导入结果继续使用现有 API 与状态，不改变后端协议。
- 导入错误停留在对应步骤，保留已选文件和字段映射，允许用户修正后重试。
- 导入入口同时存在于“我的”页和交易页省略号菜单。
- 从应用内进入导入页时返回来源页；直接访问 `/import` 时返回“我的”页。

## 6. 交互与错误处理

- 个人资料保存、语言切换或退出失败时，保留当前页面并显示明确错误，不提前关闭编辑界面或清空输入。
- 退出登录保持危险操作视觉，并使用现有确认与认证清理流程。
- 移动页面支持键盘操作、清晰焦点、Escape 关闭现有 Dialog、横竖屏和 safe area。
- 页面切换不得造成重复提交、账户状态复制或 Dialog 状态残留。
- 离线提示继续由现有 `OfflineBanner` 提供，本轮不新增离线业务逻辑。

## 7. 组件边界

实现应形成以下清晰边界，具体文件名可在实现计划中根据现有结构确定：

- `MobileNav`：只负责五项底部导航和当前路由状态。
- `MePage`：负责移动账户入口的信息架构与页面组合。
- 共享账户操作层：向桌面 TopBar 和 `MePage` 提供个人资料、设备、通知、帮助、语言与退出能力。
- 交易页移动布局：复用现有交易数据和动作，只改变移动端呈现与操作分组。
- 导入页步骤展示：复用现有上传、映射、错误和结果状态，只改变移动端层级。

共享层不得依赖移动页面的视觉结构；移动页面也不得复制共享业务实现。

## 8. 测试与验收

### 8.1 自动化测试

- `MobileNav` 只渲染五个 Tab，包含“我的”，不再包含固定“导入”和“设置”Tab。
- “我的”页包含个人资料、语言切换、导入、设备、通知、帮助、设置和退出入口。
- 小于 1000px 时可见 TopBar 隐藏，1000px 及以上桌面 TopBar 仍可达。
- 交易页具备新的标题动作层级、智能视图分组和移动筛选语义。
- 导入页具备三步进度、紧凑上传区、返回入口及稳定状态语义。
- 共享账户操作在桌面 TopBar 与移动“我的”页均可使用。

### 8.2 视觉与无障碍验收

至少覆盖：

- 320px 宽度。
- 常规 iPhone 竖屏。
- iPhone 横屏。
- 中文界面。
- 1000px 桌面边界。
- Chromium 与 WebKit 视觉基线。
- axe 无障碍检查，重点验证导航名称、焦点、Dialog、语言切换和触控目标。

### 8.3 回归与部署验收

- 前端 Vitest 全量通过。
- 前端 TypeScript 构建检查通过。
- E2E TypeScript 检查通过。
- Redis、后端与前端容器均为 healthy。
- `/healthz`、服务器本地前端与 `https://xledger.xanne.cloud` 返回成功。
- 部署后 `HEAD == origin/main`，工作树干净。

## 9. 不在本轮范围内

- 不修改后端 API 或数据库模型。
- 不新增 PostgreSQL 容器，不更改共用 PostgreSQL 配置。
- 不重做桌面信息架构。
- 不回退提交 `868e586` 已上线的 iOS 基础视觉改造。
- 不实现 A 方案 bottom sheet 或 C 方案 popover。
